# Container Permission Audit

This is a source-based audit of the server image and its runtime operations.
Issue #812 reports that the current shared runtime runs as root; the checked-in
Dockerfile has no `USER` directive (`deploy/Dockerfile.server:72-101`). This
audit does not establish that a reduced UID/capability profile works on the
deployed Fly Machine. Do not change the runtime identity or capabilities based
on this inventory alone.

## Decision

Keep the current identity and capability configuration unchanged. The checked-in
Dockerfile, Compose files, and Fly manifest do not declare a non-root user,
capability set, or TUN device. The image's Tailscale path performs network and
filesystem operations that are not proven to work under a restricted profile;
the current deploy is also not validated against the externally hosted
TrustGraph dependency. A privilege reduction could silently disable private
retrieval or break persistent state, so a source-only audit is insufficient
evidence for changing it.

The entrypoint starts `tailscaled` as a background process and then `exec`s the
supervisor; it does not stop the daemon after initialization. Therefore,
privileged initialization is not currently a short-lived setup phase that can
simply finish before dropping the application UID. A split identity would need
to isolate the long-lived Tailscale daemon from backend/supervisor processes,
and validate shared network, DNS, `/data/tailscale`, and shutdown behavior.

Before proposing a non-root/capability change, validate the actual built image
and the supported deployment path with Tailscale disabled and enabled, including
database creation/WAL writes, settings read and authenticated update, operator-link reset backup/removal, clean
shutdown, Litestream replication where configured, and the external TrustGraph
connectivity path. Record effective UID/GID, Linux capabilities, device access,
and `/data` ownership from that run. No production mutation is authorized by
this audit.

## Evidence limits

- Docker runtime validation could not run: the Docker API named pipe returned
  access denied.
- No Fly credentials/deployment or PC-hosted TrustGraph access was used.
- This document reports repository source/configuration facts only; it is not a
  claim that any candidate least-privilege profile is compatible.
